# Governance, incidents and budget

Local recommendation states are draft, validated, prepared, deferred, stale and failed. Remote approval states are pending, approved, rejected, expired, applied and lapsed. Applied recommendations start a monitor. Promotion and rollback are separate proposals and lifecycle events. A local hold never claims remote cancellation. Persist both statuses and the next deadline.

Read current policy and version immediately before dispatch. Store stable proposal ID, full intended config, typed field diff, rationale, evidence watermark, affected population and coverage. Merge only compatible changes on one base with one owner. Count submissions in a rolling 24-hour window, reserve one slot where policy allows, use approver timezone and latency estimates, and process apply-by deadlines ahead of ordinary evaluation. Let the API enforce TTL, apply window and base-version CAS. An expiry or stale base retires the intent. A new recommendation needs fresh evidence and a new ID. Config history resolves ambiguous sends. An approved apply references the actual approval ID.

Only allow auto-apply for caller-ID-only shifts when enabled and within allowed dimensions and normalized total variation. Prompt changes and prompt rollbacks require the matching passing validation receipt. On supervisor edits, suspend affected experiments, hold stale effects and rebuild recommendations on current state. Rollback patches only dimensions attributable to the harmful application and checks for later edits.

Classify severity by materiality, population and trend. Proposed P1 is a supported prompt safety spike or severe guardrail deterioration. P2 is sustained DID weakness with a healthy comparator. P3 is unconfirmed drift. For prompt spikes, begin with 200 connected observations, at least 4% flags and an exact test against a calibrated reference with a 2% floor and 5% cap. Use fixed prefixes and episode spending. Escalate unresolved flags or suspicious baseline drift for human review. A QA flag is a noisy measurement. DID screening starts with 300 recent and 600 reference dials, at least a 5 pp material decline and contemporaneous comparisons by cohort/time. Validate the alternative's eligibility and available exposure. When all DIDs fall together investigate the workflow before shifting traffic.

Arbitrate after collecting all safety signals. Choose by severity, deadline, effect population and wait age with deterministic tie-breaking. Reserve up to 15 credits for one 3-credit suggestion and three 400-call validations, keep a scenario-wide emergency floor and bound each tenant's outstanding reservations. Release unused reservations at terminal states. Unknown receipts remain reserved until reconciled. On exhaustion or no safe candidate, record a deduplicated escalation. Prefer passing candidates with credible engagement evidence. After apply, verify actual version exposure and separate KPI and safety outcomes against a stated comparison. Persistent harm starts a separately governed rollback or escalates if no safe rollback exists.

The evaluation dispatcher orders active prompt incidents by detection time, using the rotating workflow order for ties. A durable 15-credit bundle and one outstanding bundle per tenant protect incident work across restarts. The allocator holds other outstanding bundles against the observed balance. Ambiguous paid receipts conservatively retain the hold until reconciliation or prompt replacement. This allocator does not implement production quotas or proportional allocation.
